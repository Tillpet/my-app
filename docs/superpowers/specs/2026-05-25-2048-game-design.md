# 2048 Game Design Spec

## Overview

A fully runnable 2048 game built with Phaser 3 inside the existing Next.js App Router project. Accessible at `/2048`, standalone full-screen with no shared layout.

## Tech Stack

- Phaser 3 (latest stable) — game rendering and logic
- Next.js 16 App Router — hosting the game page
- TypeScript
- No additional dependencies beyond `phaser`

## Project Structure

```
src/
  app/
    (game)/
      2048/
        page.tsx          # "use client", mounts game container
  game/
    phaserGame.ts         # Creates & returns Phaser.Game instance
    config.ts             # Phaser config (Scale.RESIZE, scenes, etc.)
    scenes/
      GameScene.ts        # Grid logic + tile rendering + animations
      UIScene.ts          # Score display, win/lose overlay, restart button
    logic/
      grid.ts             # Pure functions: move, merge, spawn, win/lose check
      types.ts            # Grid state types, TileData, Direction
```

## Game Logic (`logic/`)

### types.ts

- `Direction`: enum — `Up`, `Down`, `Left`, `Right`
- `TileData`: `{ id: number, value: number, row: number, col: number }`
- `GridState`: 4x4 array of `TileData | null`
- `MoveResult`: `{ grid: GridState, score: number, moved: boolean, mergedTiles: TileData[] }`

### grid.ts — Pure Functions

- `createEmptyGrid()` → fresh 4x4 grid of nulls
- `spawnTile(grid)` → new grid with random 2 (90%) or 4 (10%) in an empty cell
- `moveGrid(grid, direction)` → slides + merges, returns `MoveResult` with score delta and merged tile positions
- `canMove(grid)` → checks if any valid move exists
- `hasWon(grid)` → checks if any tile value is 2048

Merge rules: each tile merges at most once per move (standard 2048). Processing order follows the direction of the slide (e.g., left slide processes columns left-to-right).

## GameScene — Rendering & Animation

### Initialization

- Creates background grid (4x4 rounded rectangles as empty cell slots)
- Initializes grid state via `createEmptyGrid()` + 2 `spawnTile()` calls
- Renders initial tiles
- Starts UIScene as overlay

### Input

- Arrow key events via `this.input.keyboard.on('keydown', ...)`
- On key press: `moveGrid()` → if moved → animate → spawn → update UIScene score
- After each move: `hasWon()` / `canMove()` checks for win/lose

### Rendering

- Each tile = Phaser container (rounded rect background + value text)
- Tile colors mapped by value: 2=light, 4=beige, 8=orange, 16=red-orange, 32=red, 64=deep red, 128=yellow, 256=yellow, 512=yellow, 1024=yellow-gold, 2048=gold
- Responsive: on resize, recalculates cell size and repositions all elements

### Animations (Phaser Tweens)

- **Slide**: tile tweens from old position to new position, ~150ms
- **Merge**: after slide completes, merged tile pulses scale 1.0 → 1.15 → 1.0, ~100ms
- **Spawn**: new tile fades in with scale 0 → 1.0, ~120ms
- Animation chain: slide completes → spawn + merge pulse → input re-enabled
- Input locked during animations to prevent state corruption

### Restart

- Receives event from UIScene, resets grid, clears tile containers, re-spawns 2 tiles

## UIScene — Score & Overlays

### Layout

- Overlay scene with transparent background
- Score positioned at top of canvas

### Score Display

- "SCORE" label + current score value
- Updates via event from GameScene: `scoreUpdate`
- Brief scale pulse animation on score change

### Win Overlay

- Semi-transparent dark overlay, full canvas
- "You Win!" centered text
- "Play Again" button (rounded rect + text) → emits restart event

### Lose Overlay

- Same overlay pattern: "Game Over" text + "Try Again" button
- Triggered by `gameOver` event from GameScene

### Restart Button

- Top-right corner, always visible during gameplay
- Rounded rectangle with "↺" icon text
- On click → emits restart event to GameScene

### Responsive

- All positions recalculated on resize, centered and proportional

## Next.js Integration

### page.tsx

- `"use client"` directive
- No top-level Phaser import — dynamic import inside `useEffect`
- Mounts `<div id="game-container">`
- Cleanup on unmount: `game.destroy(true)`
- Guard against React Strict Mode double-init using a ref flag

### phaserGame.ts

- Dynamically imported by page.tsx
- Creates `Phaser.Game` with config from `config.ts`
- Single responsibility: instantiate and return game instance

### config.ts

- `type: Phaser.AUTO`
- `scale: { mode: Phaser.Scale.RESIZE, parent: 'game-container' }`
- `scene: [GameScene, UIScene]`
- `transparent: true` ( UIScene needs transparency for overlay)

## Constraints

- Phaser runs client-side only — no SSR
- No external state management libraries
- No pixi.js, three.js, or UI frameworks
- Only `phaser` added as a new dependency
