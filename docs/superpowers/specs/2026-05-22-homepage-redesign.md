# Homepage Redesign — Design Specification

## Phase 1: Analysis of Current Problems

### UI Design Problems
- **Empty page**: `page.tsx` returns `<></>` — zero visual content
- **No brand identity**: No logo, no color usage, no visual personality
- **Navigation is bare**: No padding, no max-width, no visual hierarchy — links float unanchored
- **No dark mode consideration**: Navigation has no background differentiation in dark mode

### Information Hierarchy Problems
- **No content sections**: No hero, no features, no CTA — users land on nothing
- **Navigation has duplicate links**: "Introduction" appears twice (lines 74, 81)
- **No content priority**: All nav links are equally weighted, no visual distinction
- **No user journey**: No path from landing → understanding → conversion

### Component Structure Problems
- **`"use client"` on Navigation**: Entire nav is a client component when only mobile menu needs state
- **Hardcoded placeholder data**: `components` array with "Alert Dialog", "Hover Card" etc. — irrelevant to the app
- **Unused `ListItem` component**: Defined but never rendered
- **No responsive design**: No mobile menu, no hamburger, no breakpoint handling
- **Flat file structure**: All components in `_components/` with no section organization

### Maintainability Problems
- **Content mixed with UI**: Nav links are hardcoded in JSX, not in a config
- **No shared types**: No type definitions for navigation items, sections, features
- **No content constants**: No central place to update copy or links
- **Metadata is generic**: "Generated by create next app" — not real SEO

### Responsiveness Problems
- **No mobile nav**: Desktop-only layout, breaks on small screens
- **No responsive spacing**: No container queries or breakpoint-aware padding
- **No responsive typography**: No size scaling across breakpoints

### Scalability Problems
- **No section system**: Adding a new section means editing the monolithic page
- **No content-driven architecture**: No data/config layer to drive sections
- **No component library**: Each section would be built from scratch

## Phase 2: Architecture Design

### Section-Based Architecture

```
src/app/(Home)/
├── layout.tsx                          # Layout with Navbar + Footer
├── page.tsx                            # Composes sections
├── _components/
│   ├── navbar.tsx                      # Desktop + mobile nav (server-first)
│   ├── mobile-nav.tsx                  # Client component for mobile menu
│   ├── hero-section.tsx                # Hero with headline, CTA, visual
│   ├── features-section.tsx            # Feature grid/cards
│   ├── showcase-section.tsx            # Product showcase / demo area
│   ├── stats-section.tsx               # Social proof / metrics
│   ├── cta-section.tsx                 # Final call-to-action
│   └── footer.tsx                      # Site footer
├── _content/
│   └── index.ts                        # All homepage content/config (SEO, nav items, features, stats, CTAs)
└── _types/
    └── index.ts                        # Shared type definitions
```

### Design Principles
- **Server Components by default**: Only mobile-nav is `"use client"`
- **Content-driven**: All copy, links, feature data live in `_content/index.ts`
- **Composable sections**: Each section is self-contained, receives data as props
- **SEO at the page level**: Metadata export in `page.tsx`

### Data Flow
```
page.tsx
  → imports content from _content/index.ts
  → passes section data as props to each section component
  → each section renders independently
```

## Phase 3: Design Upgrade

### Visual Direction
**Style**: Modern SaaS / Premium AI Product (inspired by Vercel, Linear, OpenAI, Stripe)

### Design Tokens
- **Typography**: Geist Sans (already configured) — clean, geometric, modern
- **Colors**: Leverage existing neutral theme with accent highlights
- **Spacing**: 8px grid — generous whitespace, breathing room between sections
- **Border radius**: Existing `--radius` system (0.625rem base)

### Layout Principles
- **Max-width container**: `max-w-7xl mx-auto` with responsive padding
- **Section spacing**: `py-24 md:py-32` between sections
- **Content width**: Text blocks `max-w-3xl`, feature grids `max-w-6xl`
- **Vertical rhythm**: Consistent heading sizes — h1: 5xl/6xl, h2: 3xl/4xl, body: lg

### Sections Design

#### 1. Navbar
- Sticky, blurred background (`backdrop-blur-xl bg-background/80`)
- Logo on left, nav links center, CTA button + login right
- Mobile: hamburger menu (sheet-based)
- Subtle bottom border on scroll

#### 2. Hero Section
- Large headline (gradient text on key phrase)
- Subtitle with muted-foreground
- Two CTAs: primary (filled) + secondary (outlined)
- Optional: subtle grid/dot pattern background
- Centered layout, generous padding

#### 3. Features Section
- Section heading + description
- 3-column grid (responsive: 1 → 2 → 3 cols)
- Each card: icon, title, description
- Subtle border, hover elevation
- Cards use existing shadcn Card pattern

#### 4. Showcase Section
- Product screenshot or demo visual area
- Gradient border/glow effect around the visual
- Headline + description alongside or above

#### 5. Stats Section
- Row of 3-4 key metrics
- Large numbers + labels
- Subtle dividers between items
- Optional: background tint

#### 6. CTA Section
- Bold headline
- Supporting text
- Single prominent CTA button
- Centered layout

#### 7. Footer
- Multi-column link layout
- Logo + copyright
- Social links (if applicable)
- Subtle top border

### Animation Strategy
- CSS-only animations (no Framer Motion dependency)
- Fade-in on scroll using `IntersectionObserver` (single client wrapper)
- Subtle hover transitions on cards and buttons
- Respect `prefers-reduced-motion`

### Responsive Breakpoints
- Mobile: < 640px (1 column, hamburger nav)
- Tablet: 640–1024px (2 column features)
- Desktop: > 1024px (3 column features, full nav)
